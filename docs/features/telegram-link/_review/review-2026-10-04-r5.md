The delete never runs.<br>The accounts this hits are exactly the ones boot can't reopen (`BootReconnect.kt:68` catches `Exception` for this reason). Such an account is never open, so every unlink of it fails. Before T57, the same unlink returned "not confirmed" and deleted the account, as AC-113 requires. No test covers this. | AC-113 | `messaging/LinkedAccounts.kt:136,150-154`; `identity/internal/key/AesGcm.kt:35` | Fix now: catch `Exception` in `signOut` (or around `reopenIfClosed`). Add an `UnlinkIT` case that corrupts `sealed_key` and still expects `signOutConfirmed=false` and the row deleted. |
| K10 | When `deletion.delete` throws, `deleteOrClose` closes the session whatever the sign-out returned. That leaves two wrong states:<br>• **Sign-out confirmed:** the client is gone, `emitState` is muted, and the row stays `connected` or `reconnecting` with no client and no chat sync until a restart or a retried unlink.<br>• **Sign-out not confirmed:** `abandonLogOut` had already unmuted a valid session that would reconnect by itself. Closing it stops it, and `markClosing` mutes the late Closed that `abandonLogOut` was meant to let through.<br>The `UnlinkIT` predicate `state == "session_lost" \|\| !fake.isOpen(session)` passes on this false state. Found by two reviewers. | AC-122, AC-121 | `messaging/LinkedAccounts.kt:97-110`; `telegram/internal/tdlight/TdlightSession.kt:274,289-290`; `TdlightTelegramSessions.kt:152-154`; `UnlinkIT.kt:246` | Fix now:<br>• Sign-out confirmed: close the session and move the row to `SESSION_LOST`, because Telegram really ended it.<br>• Not confirmed: leave the session open so it keeps reporting.<br>Make the `UnlinkIT` assertions check what the Owner sees: the row state, not only `isOpen`. |
| K11 | In `LifecycleIT.kt:233-250`, the unlink's own reopen fails. The unlink then deletes the row and destroys the directory, and only after that does the boot reopen run. So the test asserts "teleX device signed out of Telegram".<br>Real TDLib would open an empty database and ask for a phone number, so it reports Closed and `logOut` returns false.
